# OFS.org · Open Full Stack

> **Open source, engenharia de software e desenvolvimento Full Stack na prática.**

O **OFS.org (Open Full Stack)** é um ecossistema open source dedicado à construção de aplicações modernas, escaláveis e orientadas a produto.

O projeto combina **aprendizado prático, engenharia de software e colaboração**, criando um ambiente para desenvolver projetos reais utilizando tecnologias e práticas presentes no mercado.

---

## Sobre o projeto

O OFS.org nasceu com uma proposta simples:

**transformar conhecimento em experiência prática.**

Aqui, conceitos de desenvolvimento de software são aplicados em projetos que envolvem arquitetura, desenvolvimento, APIs, bancos de dados, autenticação, testes, infraestrutura e deploy.

O ecossistema é voltado para desenvolvedores que desejam:

* Desenvolver aplicações reais;
* Aprimorar fundamentos de engenharia de software;
* Explorar arquiteturas modernas;
* Trabalhar com tecnologias utilizadas no mercado;
* Construir projetos para portfólio;
* Colaborar com iniciativas open source;
* Compartilhar conhecimento com outros desenvolvedores.

# Getting Started

Escolha um dos projetos disponíveis na organização e siga as instruções específicas presentes em seu respectivo repositório.

### Clone um projeto

```bash
git clone https://github.com/OFS-org/<repository>.git
cd <repository>
```

### Instale as dependências

```bash
pnpm install
```

> Os comandos podem variar de acordo com o projeto. Consulte o `README.md` de cada repositório antes de iniciar o desenvolvimento.

# Contributing

O OFS.org é construído de forma colaborativa.

Contribuições são bem-vindas, desde correções e melhorias até novas funcionalidades e documentação.

### Fluxo sugerido

```bash
# Crie uma branch
git checkout -b feature/minha-feature

# Faça suas alterações
git add .

# Registre o commit
git commit -m "feat: nova funcionalidade"

# Envie sua branch
git push origin feature/minha-feature
```

Depois, abra um **Pull Request** descrevendo as alterações realizadas.

### Conventional Commits

Sempre que possível, utilize mensagens de commit semânticas:

```text
feat: adiciona autenticação
fix: corrige validação do formulário
docs: atualiza documentação
refactor: reorganiza camada de serviços
test: adiciona testes para autenticação
chore: atualiza dependências
```
